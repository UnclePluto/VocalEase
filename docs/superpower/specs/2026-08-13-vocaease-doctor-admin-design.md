# VocaEase 医生后台与共享服务设计规格

日期：2026-08-13
状态：已确认，待用户审阅书面规格

## 1. 背景与目标

VocaEase 用唱歌训练辅助治疗胃上嗳气。完整产品最终由医生后台、患者 Android 端和 AI 算法服务组成。本期从零重建项目，交付可真实运行的医生后台和共享服务端，并为患者 Android 端预留稳定 API。AI 能力只实现任务协议、状态流转和模拟执行器，不实现真实算法。

本期目标：

- 高度还原 `docs/design.pen` 中的医生后台视觉稿和交互。
- 实现真实认证、数据库持久化、业务 API、媒体上传、异步任务、统计和数据导出。
- 提供未来 Android 患者端可直接使用并有自动化测试的 API。
- 将媒体存储封装为可替换服务；本地开发默认使用本地文件，正式环境使用七牛云私有空间。
- 通过 Docker Compose 在本地一键启动完整系统。

## 2. 本期范围

### 2.1 包含

- 医生后台的登录、医生管理、病人管理、曲库管理、病人数据、唱歌明细和数据管理。
- 视觉稿中的新增、编辑、删除、上传、试听、筛选、分页、多选和确认弹窗。
- 系统管理员、医生、患者三类账号。
- JWT 登录、刷新、退出、首次强制改密和管理员重置密码。
- PostgreSQL 数据持久化、Redis、Celery 异步任务。
- 七牛云私有空间直传、回调验签和短时授权访问；本地等价存储实现。
- 歌曲分析和演唱分析的模拟任务。
- Excel（`.xlsx`）与 CSV 导出。
- OpenAPI 文档、演示数据、自动化测试和本地运行说明。

### 2.2 不包含

- Android App。
- 真实人声分离、伴奏生成、歌词识别或 MediaPipe 面部分析。
- 临床诊断结论或算法有效性判断。
- 阿里云远端部署、GitHub CI/CD 和 Kubernetes 编排。
- 平板或手机尺寸的医生后台。
- PDF 报告。

## 3. 已确认的技术方案

采用前后端分离的模块化 Django 单体：

- `web-admin`：React、TypeScript、Vite、Ant Design。
- `server`：Django、Django REST Framework。
- 数据库：PostgreSQL。
- 缓存与任务队列：Redis、Celery。
- 媒体：本地存储适配器或七牛云私有空间适配器。
- 入口代理：Nginx。
- 本地编排：Docker Compose。

首期不建立独立 AI 微服务。模拟算法通过 Django 内的执行器接口运行；未来真实服务实现同一任务协议后即可拆出，而无需更改前端或患者 API。

## 4. 仓库边界

建议的顶层结构：

```text
VocaEase/
├── web-admin/          # React 医生后台
├── server/             # Django 服务端
├── deploy/             # Docker、Nginx 和本地编排配置
├── docs/               # 本地项目文档和视觉稿；默认被 Git 忽略
├── AGENTS.md
└── .gitignore
```

本规格按项目宪法单独强制纳入 Git；`docs/design.pen` 和其他 `docs/` 内容继续忽略。

## 5. Django 模块边界

- `accounts`：统一用户、角色、JWT、首次改密、密码重置和令牌吊销。
- `doctors`：医生资料、状态和逻辑删除。
- `patients`：患者资料、主治医生和治疗计划。
- `songs`：歌曲元数据、发布状态、媒体关联和歌曲分析状态。
- `singing`：演唱任务、演唱媒体、结果与历史记录。
- `analysis`：统一任务协议、模拟执行器、状态、结果和重试。
- `analytics`：汇总指标、趋势、改善率和 Excel/CSV 导出。
- `media`：上传策略、本地/七牛适配器、回调和授权 URL。
- `audit`：关键操作审计。

模块只通过明确的服务接口或模型关系协作。视图层不直接调用七牛 SDK、Celery 任务实现或跨模块内部函数。

## 6. 身份、认证与权限

### 6.1 角色

- `system_admin`：拥有全部后台功能、系统级配置、Django Admin 和审计日志权限。
- `doctor`：可查看和管理全部医生、患者、歌曲、演唱记录、统计和导出；当前不按主治关系做数据隔离。
- `patient`：只能访问本人资料、当前治疗计划、可用歌曲、本人演唱任务和历史记录。

权限在 API 层强制执行；前端菜单隐藏不作为安全边界。Django Admin 使用独立的 `/internal/admin/` 入口，只允许系统管理员访问。

### 6.2 账号规则

- 医生以唯一工号登录，患者以唯一病历号登录。
- 新建医生或患者后初始密码固定为 `888888`。
- 首次登录必须修改密码。未改密账号只能访问登录、刷新、改密和退出接口。
- 管理员或医生执行“重置密码”后，密码恢复为 `888888`，并重新要求首次改密。
- 医生工号和患者病历号由服务端生成，删除后不复用。

### 6.3 令牌

- 访问令牌默认有效期 15 分钟。
- 刷新令牌默认有效期 1 天；选择“记住我”时为 30 天。
- 医生后台的刷新令牌使用 Secure、HttpOnly、SameSite Cookie 保存，并通过来源校验和 CSRF 防护刷新；未来 Android 患者端通过响应体接收刷新令牌并由系统安全存储保存，不要求原生客户端依赖浏览器 Cookie。
- 刷新令牌每次使用后轮换，旧令牌立即失效；服务端只保存可撤销的令牌摘要。
- 改密、重置密码、停用或删除账号会吊销该用户全部刷新令牌。

## 7. 核心数据模型

### 7.1 用户与治疗

- `User`：UUID、角色、登录账号、密码、启停状态、首次改密标记、最后登录时间、逻辑删除时间。
- `DoctorProfile`：工号、姓名、性别、手机号、科室、职称、创建时间。
- `PatientProfile`：病历号、姓名、性别、入组年龄、手机号、病情备注、当前主治医生、创建时间。
- `TreatmentPlan`：患者、开始日期、周期周数、目标演唱次数、状态、结束日期、备注。患者可保留多轮计划，但同时最多一个活动计划。

主治医生是治疗信息，不是数据访问边界。入组年龄作为治疗阶段快照保存，避免随时间自动变化导致历史报表不一致。

### 7.2 歌曲与媒体

- `Song`：歌名、歌手、曲风、语言、时长、分析状态、发布状态、上传时间、逻辑删除时间。
- `MediaAsset`：所有者类型、所有者 ID、资源类型、存储后端、对象键、MIME、字节数、哈希、上传状态和元数据。

资源类型至少包括：歌曲源文件、伴奏、人声、歌词、演唱音频、演唱录像、波形峰值数据和导出文件。数据库不保存七牛永久访问地址。

### 7.3 演唱与分析

- `SingingSession`：患者、歌曲、开始/结束时间、时长、状态、综合得分、嗳气次数、模拟结果标记和创建来源。
- `AnalysisTask`：目标类型、目标 ID、任务类型、协议版本、状态、进度、输入、结果、错误码、错误摘要、重试次数和幂等键。
- `AnalysisTimeSeries`：任务、指标类型、采样间隔和压缩后的时间序列，用于明细页随播放进度展示。

演唱状态：`created → awaiting_upload → uploaded → processing → completed`，失败进入 `failed`，未提交任务可进入 `cancelled`。分析状态：`pending → processing → succeeded`，异常进入 `failed`，重试期间进入 `retrying`。

### 7.4 审计与导出

- `AuditLog`：操作人、角色、动作、对象类型、对象 ID、变更摘要、请求追踪 ID、来源 IP 和时间。
- `ExportJob`：创建人、筛选条件、格式、状态、结果媒体、失败原因和过期时间。

## 8. 逻辑删除与历史一致性

- 医生、患者和歌曲只做逻辑删除，不直接物理删除关联数据或七牛文件。
- 删除患者会立即停用账号并从常规列表隐藏，但治疗、演唱和媒体历史继续保留。
- 删除歌曲后不可创建新的演唱任务，历史记录仍显示保存的歌曲快照。
- 有在治患者的医生不可删除，必须先完成主治医生重新分配。
- 物理清理属于未来单独的管理员流程，不在本期范围。
- 新增、编辑、启停、重置密码、删除、导出和媒体授权均记录审计日志。

界面删除提示必须说明“停用并隐藏、历史保留”，不得继续显示“所有数据不可恢复”等与实际行为冲突的文案。

## 9. 医生后台页面

### 9.1 登录页

- 账号、密码、记住我、登录错误提示。
- 首次登录成功后只能进入强制改密流程。
- 改密成功后吊销原令牌并重新登录。

### 9.2 医生管理

- 姓名/工号搜索、科室筛选、重置、分页。
- 新增、编辑、启停、重置密码和逻辑删除。
- 服务端自动生成工号；手机号、工号唯一性由服务端校验。
- 视觉稿的新增/编辑弹窗缺少列表所需的“科室、职称”字段；实现时在保持现有弹窗视觉语言的前提下补充这两个必填项，使列表字段能够由后台完整维护。
- 有在治患者时拒绝删除并返回可操作提示。

### 9.3 病人管理

- 姓名/病历号搜索、治疗状态筛选、重置、分页。
- 新增、编辑、逻辑删除和查看患者数据。
- 服务端自动生成病历号。
- 主治医生下拉仅列出启用且未删除的医生。

### 9.4 曲库管理

- 歌名/歌手搜索、分页、上传、编辑、试听、重新分析、上下架和逻辑删除。
- 音频默认最大 50 MB，允许 MP3、WAV、FLAC；限制可由环境变量收紧。
- 浏览器先获取上传凭证，再直传本地存储或七牛，服务端收到可信完成通知后创建媒体记录。
- 可选择上传后自动创建模拟歌曲分析任务。
- 分析产物只在对应媒体真实存在时允许试听或下载；模拟任务不会把源文件伪装成分离后的媒体。

### 9.5 病人数据

- 展示患者资料、活动治疗计划和演唱汇总。
- 历史演唱支持日期范围筛选、分页和进入明细。
- 编辑患者资料复用病人管理表单规则。

### 9.6 唱歌明细

- 展示患者、歌曲、演唱时间、时长、得分和嗳气次数。
- WaveSurfer.js v7 负责录音波形、播放进度、时间轴、点击跳转、悬停时间和嗳气事件区域标记。
- Waviz 负责播放过程中的实时频域/时域 Canvas 动效。
- 多轨模式包括“人声 + 伴奏”“仅人声”“仅伴奏”，共享播放进度；缺少某一轨时禁用对应选项并说明原因。
- 指标卡按当前播放时间读取模拟时间序列，展示音量、基频、信噪比和嗳气事件。
- 录像和音频使用同一主时钟同步播放；浏览器限制自动播放时，等待用户主动点击。
- Waviz 封装在独立适配组件内；兼容性不达标时可替换为 Web Audio API + Canvas。
- “实时”仅指随历史录音回放实时变化，不表示现场采集或临床监测。

### 9.7 数据管理

- 汇总在治患者数、累计演唱、平均得分和每次演唱平均嗳气次数。
- 患者列表显示治疗进度、演唱次数、累计时长、平均得分、得分趋势和嗳气改善率。
- 单条或多选导出 `.xlsx` 或 `.csv`，导出内容遵循当前筛选条件。
- 结果不超过 1,000 行时同步生成；超过 1,000 行时创建异步导出任务。
- CSV/Excel 单元格对以 `= + - @` 开头的文本进行安全转义，避免公式注入。

## 10. 统计口径

- 在治患者：当前存在状态为“治疗中”的活动治疗计划且患者未删除。
- 累计演唱：状态为 `completed` 的演唱记录数。
- 平均得分：所有有有效得分的已完成演唱记录算术平均值。
- 平均嗳气次数：所有有有效分析结果的已完成记录嗳气次数算术平均值。
- 治疗进度：已完成演唱次数与治疗计划保存的目标演唱次数之比，上限为 100%。新计划默认按每周 3 次生成目标次数，创建后作为计划快照保存，后续调整系统默认值不会改写历史计划。
- 得分趋势：比较最近三次和之前三次有效演唱的平均得分；少于六次时显示“数据不足”。
- 嗳气改善率：先计算每次演唱的每分钟嗳气次数；最早三次有效演唱的平均值作为基线，最近三次作为当前值，公式为 `(基线 - 当前值) / 基线 × 100%`。少于三次或基线为零时显示“暂无趋势”。

所有统计接口同时返回口径版本，未来调整口径时能够区分历史结果。

## 11. 患者端预留 API

患者 API 使用 `/api/v1/patient/` 命名空间，提供：

- 登录、刷新、首次改密和退出。
- 获取本人资料及活动治疗计划。
- 分页获取已上架歌曲和歌曲详情。
- 创建演唱任务。
- 获取音频/录像上传凭证。
- 确认上传和提交演唱任务。
- 查询处理状态、本人演唱历史和单次结果。

管理后台 API 使用 `/api/v1/admin/`，通用认证使用 `/api/v1/auth/`。OpenAPI Schema 和交互文档由 Django 服务端生成。

## 12. 演唱上传与分析数据流

1. 患者选择歌曲并创建 `SingingSession`。
2. 服务端校验患者、活动治疗计划和歌曲状态。
3. 服务端为本次会话生成受限对象键和上传凭证。
4. 客户端将音频和录像直传本地存储或七牛私有空间。
5. 七牛回调服务端；服务端校验回调签名、对象键、MIME、大小和哈希并登记 `MediaAsset`。
6. 患者提交会话。幂等键保证重复请求不会创建重复任务。
7. Celery 执行模拟分析，生成带 `is_mock: true` 和协议版本的得分、事件和时间序列。
8. 患者端轮询状态；后台可查看完成结果。

录像默认最大 500 MB，允许的 MIME 和上限均由环境变量配置。上传凭证默认 15 分钟有效，只能写入指定对象键。私有下载地址默认 10 分钟有效。

## 13. 歌曲模拟分析协议

歌曲任务类型预留：

- `vocal_separation`
- `accompaniment_generation`
- `lyrics_recognition`

模拟执行器只验证任务流程并返回结果清单、协议版本、模拟标记和可预测的演示数据，不声称生成了真实算法产物。演示数据可关联预置媒体以测试播放；用户新上传歌曲只有真实存在的资源才能作为分析产物访问。

未来独立 AI 服务必须遵守以下边界：

- 输入仅包含任务 ID、受限媒体引用、任务类型和协议版本。
- 输出包含任务 ID、状态、产物清单、指标、错误码和协议版本。
- 回调或消息处理必须幂等。
- Django 是业务状态和授权的唯一事实来源，AI 服务不能直接修改患者权限或治疗数据。

## 14. 存储设计

定义统一 `StorageBackend` 接口：

- 创建受限上传策略。
- 验证上传完成通知。
- 判断对象是否存在并读取元数据。
- 创建短时私有访问地址。
- 标记待清理对象。

实现：

- `LocalStorageBackend`：默认开发模式，模拟直传、私有访问和完成回调；自动化测试使用隔离临时目录。
- `QiniuStorageBackend`：正式环境使用七牛私有空间、上传凭证、回调验签和短时授权 URL。

对象键由服务端生成，按环境、资源类型、日期和 UUID 分层，不包含姓名、手机号、病历号等敏感信息。七牛空间必须配置医生后台和患者端允许来源的 CORS，否则浏览器端 WaveSurfer 无法解码媒体。

## 15. 错误处理与幂等

统一错误响应包含：

- 稳定错误码。
- 用户可读提示。
- 可选字段级错误。
- 请求追踪 ID。

规则：

- 上传、分析和导出使用显式任务状态，不保持长时间 HTTP 请求。
- 获取上传凭证、七牛回调、确认上传、提交演唱、分析回调和任务重试均支持幂等。
- 任务失败保存错误码和脱敏摘要，允许重新执行；失败任务不写入半完成分析结果。
- 前端统一处理登录过期、首次改密、无权限、校验失败、网络失败和任务失败。
- 逻辑删除对象对新写操作表现为不存在，但历史只读接口可返回必要快照。

## 16. 安全与隐私

- 使用 Django 标准密码哈希，不保存或记录明文密码。
- 登录、刷新、改密、重置密码和上传凭证接口实施频率限制。
- 手机号在列表和日志中脱敏；仅授权详情接口返回完整值。
- 七牛密钥、数据库密码和 Django Secret Key 仅从环境变量读取。
- 仓库只提供不含真实秘密的 `.env.example`。
- 日志不得记录密码、JWT、刷新令牌、七牛签名或完整病情备注。
- 私有媒体访问会记录操作人、资源、时间和请求追踪 ID。
- 前端不得缓存永久媒体地址，授权地址过期后重新请求。
- 模拟分析结果在 API 和界面语义中标记为非临床、非真实算法结果。

## 17. 日志与健康检查

- Django 和 Celery 输出结构化日志，携带请求追踪 ID 或任务 ID。
- 健康检查分别报告应用进程、PostgreSQL、Redis、Celery 和存储配置状态。
- 本地环境直接通过容器日志诊断。
- 为未来阿里云日志服务和监控接入保留标准输出与健康检查端点，不在本期配置云资源。
