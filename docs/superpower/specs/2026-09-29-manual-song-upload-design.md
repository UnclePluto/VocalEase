# 曲库人工上传设计

日期：2026-09-29
状态：设计方案已确认；本文待用户审核，尚未进入实现。

## 目标与已确认需求

管理员可以在曲库点击「人工上传」，填写歌曲信息并上传已准备好的音频与歌词，不依赖自动分离或识别。

- 原曲：人声与伴奏混合的完整歌曲，必传。
- 纯人声：去掉伴奏后的演唱，选填。
- 纯伴奏：去掉人声后的音乐，选填。
- LRC 歌词：带时间标签的歌词文件，选填。
- 支持后续补传或替换选填资源；保存为未发布歌曲。
- 人工上传不自动创建分析任务；后台可试听不同音轨、查看歌词和资源齐全情况。

## 现状与方案选择

当前后台的 SongUploadModal 只上传原曲，SongUploadIntent 绑定预分配歌曲标识与原曲资产。媒体层已支持 song_source、song_vocal、song_accompaniment、lyrics 四种类型，本地和七牛存储均有上传完成验证。

Song 仅直接关联 source_asset；试听窗口的人声、伴奏按钮固定禁用。发布服务要求当前原曲存在成功分析结果，无法直接支持不分析的人工歌曲。

采用「歌曲直接关联人工资源」：保留原曲关联，为三个选填资源新增关联，复用现有媒体上传、存储验证和私有访问机制。资源与分析任务解耦。

不采用将人工资源伪装成分析结果的方案，避免混淆分析状态与文件可用性；不建立独立曲库或第二套存储系统，以保持现有曲库查询与患者原曲播放兼容。

## 管理员交互

1. 曲库保留现有上传入口，新增「人工上传」。表单沿用歌曲名称、歌手、曲风、语言、时长字段。
2. 四个文件选择区分别标明用途、格式和必填状态。未选择原曲时禁止提交。
3. 音频支持 MP3、WAV、FLAC，单文件不超过 50MB，并遵循服务端配置的更低上限；禁止空文件。
4. LRC 接受 .lrc 文件，以 text/plain 上传；上限为 1MB，若媒体层限制更低则遵循更低值。
5. 表单显示各文件上传状态及错误。全部已选择文件验证通过后，才创建歌曲并关闭弹窗；失败时可重试，已确认文件不重复上传。
6. 歌曲行展示原曲、人声、伴奏、歌词的已上传/未上传状态；人工歌曲显示「人工上传」，不因为资源保存成功而显示「分析完成」或「模拟分析」。
7. 人工歌曲提供「管理资源」，补传或替换三个选填文件，保留未修改资源。上传过程中继续使用旧版本，保存成功后切换。
8. 试听窗口启用已上传音轨，切换时停止旧音轨并取消旧请求；缺失音轨不可点击。歌词以时间与正文列表呈现，暂无逐字高亮或跟随播放滚动。

此次资源管理不提供删除资源或替换原曲的界面，不新增患者端音轨切换界面。

## 数据结构与上传契约

- Song 增加 ingestion_mode，取值为 existing/manual，历史歌曲和旧接口请求默认为 existing。
- Song 增加可空的 vocal_asset、accompaniment_asset、lyrics_asset 外键，使用 PROTECT；每首歌每类资源只有一个当前版本。
- 人工上传入口显式指定 manual 模式；现有上传入口继续使用既有行为。模式创建后不可由通用歌曲编辑接口修改。
- 原曲仍通过歌曲专属上传凭证预分配 song_id 并建立 SongUploadIntent。扩展歌曲上传凭证请求，允许为已存在且未删除的歌曲或有效上传意图申请选填资源，未指定媒体类型时仍按原曲处理。
- 新增歌曲请求可携带三个选填资产标识；服务端必须验证资产属于该歌曲、类型匹配、未删除、上传完成且存储对象与可信回执一致。所有关联与歌曲创建在同一数据库事务内生效。
- 人工模式不得触发 auto_analyze；与 auto_analyze=true 同时提交时明确拒绝，不静默忽略。
- 新增管理员资源更新接口，仅操作人工歌曲的三个选填关联。请求包含待更新字段及对应旧资产标识；事务内加锁并比较旧值，冲突返回 409，防止同时操作时覆盖他人更新。省略字段表示保持原样，null 不作为删除操作。
- 更新与新建响应返回当前资源标识、录入模式及资源存在信息；不向列表直接暴露存储地址。
- 上传凭证、资源绑定、资源替换、歌词读取和试听授权均遵循现有管理员权限与审计规则。

## LRC 校验与展示

服务端在绑定歌词前读取已验证的资产内容，执行大小与内容校验，不能仅依赖文件扩展名或前端解析。

- 支持 UTF-8 和 UTF-8 BOM；其他编码提示转换为 UTF-8。
- 支持 [mm:ss]、[mm:ss.xx]、[mm:ss.xxx] 时间标签及同一行多个时间标签；秒数必须小于 60。
- 支持标准 ti、ar、al、by、re、ve、length 元数据和毫秒 offset 标签。offset 应用后负时间归零。
- 至少存在一条带有效时间标签且正文非空的歌词；时间标签错误、未知标签或无法解释的非空行返回行号及原因。空行可忽略，空正文时间点可保留为空白分隔。
- 解析后按时间稳定排序，重复时间保留原有顺序，正文按纯文本渲染。
- 原始 LRC 文件保留在媒体存储。新增管理员歌词读取接口，读取当前已绑定且验证可用的文件并返回规范化时间与正文；本次不额外持久化解析副本。

## 发布与分析状态

这是为使人工上传流程可用而补充的规则，随本文审核：

- 人工歌曲创建后保持未发布；管理员明确点击发布才对患者开放。
- 人工歌曲发布要求原曲完成真实存储验证。人声、伴奏和歌词不构成发布前置条件，也不要求分析成功。
- 原有歌曲继续要求当前原曲存在成功分析结果，不能通过普通编辑请求切换录入模式来绕过。
- 不把人工上传标记为分析成功。沿用现有分析状态字段，但后台对人工歌曲显示录入模式和资源状态，不展示无任务的「待分析」轮询。
- 人工歌曲本次不提供重新分析按钮；服务端对人工歌曲的重新分析请求明确拒绝，避免生成误导性状态。
- 已发布人工歌曲补传或替换选填资源后维持发布状态，失败时旧关联保持可用。患者曲库仍依赖原曲可用性快照，现有患者原曲播放与历史演唱记录不变。

## 失败、重试与资源生命周期

- 上传沿用本地确认和七牛完成回执机制，不能仅凭浏览器上传成功就绑定资源。
- 保存歌曲响应丢失时，沿用预分配歌曲标识查询确认机制，并比较本次提交的资源与基本信息；不重复创建，也不把同标识的不同内容误判为成功。
- 资源更新响应丢失时，读取当前关联确认是否已达到目标；若存在不同修改，展示冲突并刷新。
- 部分文件失败时保留本次弹窗内已确认资产，允许重试失败项；取消会中止前端请求，但不能假设已发出的服务端写入也被撤销。
- 未绑定文件不进入曲库；遵循现有媒体生命周期，不在请求失败时直接删除已上传对象。旧版本资产保留，不在资源替换事务内物理删除，以免影响已签发地址或历史引用。
- 所有私有试听地址短期有效，读取时验证当前绑定与资产状态；切换音轨后的迟到响应不得覆盖当前播放器。

## 改动范围与兼容性

服务端主要涉及 songs 的模型、迁移、序列化、服务、视图、路由与 API 文档，并按需抽取媒体真实对象验证能力供多种歌曲资源复用。不能削弱现有原曲回执与归属校验。

后台主要涉及歌曲列表、人工上传与资源管理表单、试听窗口、歌曲 API/types 及对应测试。原有自动上传表单继续保留。

旧歌曲新增关联为空、录入模式为 existing；原曲上传与试听请求默认语义保持兼容。患者端不增加必需字段、不修改当前原曲播放流程。本次不实现音轨分离、歌词识别、音频内容同步检测或批量导入。

## 验收与测试

1. 仅上传原曲即可创建人工歌曲；缺失原曲或绕过前端直接提交时服务端拒绝。
2. 四类文件全部上传后关联正确，可分别试听三条音轨并查看歌词；任选部分选填文件也能成功。
3. 人工创建不产生分析任务；原有上传及分析发布流程回归通过。
4. 校验跨歌曲资产、错误媒体类型、未完成或已删除资产、伪造回执、超限及空文件；非管理员不能操作。
5. LRC 覆盖 BOM、多时间标签、offset、排序、元数据、空歌词、非法编码与非法时间标签。
6. 部分上传失败、取消、创建或更新响应丢失、重试、并发替换均不重复创建或错误覆盖。
7. 已发布人工歌曲可以补充选填资源，更新失败保留旧资源；人工歌曲发布仍会拒绝原曲不存在或存储验证失败。
8. 旧歌曲迁移后可正常查询、上传、试听和发布；患者列表、原曲播放、历史记录不受影响。
9. 运行相关服务端与前端测试、前端类型检查和构建、迁移一致性检查；验证本地与七牛上传契约，不要求使用真实外部账号才能执行测试。

## 规格自检

已检查必填规则、人工上传与发布的关系、资源归属和回执验证、重试与并发语义，以及与旧接口和患者端的兼容边界。本文无待定项；新增的具体格式、发布与资源管理规则由用户在规格审核时确认。
