# 医生端与安卓端演唱体验修复规格

日期：2026-10-06
状态：用户已批准本书面规格，进入实施计划评审。
依据：用户的八项体验反馈、五张截图、2026-10-06 调查报告、医生端 docs/design.pen。

## 1. 目标与范围

患者能够在试听与演唱时切换原唱、伴奏，在演唱时看到原唱参考音高块、患者实时音高白点及历史轨迹，并通过鼻子以下至颈部的引导正确取景。医生能够从患者列表进入演唱明细，查看患者真实声音波形和设计稿中的双图看板，在患者人声及患者人声＋伴奏之间切换回放。

本规格覆盖医生后台、安卓患者端和共同的歌曲/演唱媒体协议。既有治疗计划可选、无计划可唱、认证、加密草稿与断点上传规则继续适用。用户当前认证相关未提交改动由原工作保留，不纳入本次提交。

本次提供真实音频采样与音高可视化，不扩展临床嗳气识别、疗效判断或综合评分算法。现有模拟分析必须保留模拟标识。

## 2. 已确认的交互

| 场景 | 默认模式 | 允许切换 | 人声含义 |
| --- | --- | --- | --- |
| 安卓试听 | 原唱 | 原唱 / 伴奏 | 歌曲原曲包含的歌手声音 |
| 安卓演唱 | 伴奏 | 原唱 / 伴奏 | 麦克风采集的患者声音，独立录制 |
| 医生回放 | 有本次演唱绑定伴奏时默认人声＋伴奏；否则默认人声 | 人声＋伴奏 / 人声 | 麦克风采集的患者声音 |

“原唱”播放完整 song_source，而非 song_vocal。song_vocal 仅可用于生成原唱参考音高。医生端的“人声”始终来自 singing_audio，歌曲歌手人声不得替代患者声音。

切换模式保持歌曲时间位置及播放/暂停状态。安卓切换不重新创建演唱会话、不中断麦克风录制、不重置参考音高或计时。试听选择不决定演唱初始模式，开始演唱前显式切回伴奏并回到歌曲起点。

## 3. 模块与数据流

```text
歌曲原曲 / 伴奏 ──> 带模式的播放器 ──> 歌曲主时钟
歌曲人声或可信标注 ──> 版本化参考音高 ──> 滚动音高块
单一 AudioRecord ──> PCM ──┬─> 实时音高检测 ──> 患者白点 / 轨迹
                          └─> AAC 编码 ──> 患者音频文件
CameraX（关闭麦克风） ──> 视频 ──> 按时间戳合并患者 AAC ──> 录像文件
患者音频 + 录像 + 播放元数据 ──> 现有加密草稿 / 上传 / 演唱会话
医生端授权的患者音频 ──┬─> WaveSurfer 总览
                       ├─> 共享 Web Audio 分析器 ──> 时序图 / 极坐标图
                       └─> 回放主时钟 ──> 录像 + 可选歌曲伴奏
```

新增模块分别承担音高检测、参考音高读取、单一音频采集、音视频合并和双图渲染。UI 仅消费状态，重试与资源释放由现有 coordinator/repository 边界承担。不得把所有逻辑塞入 RecordingScreen 或 WaveformPlayer。

## 4. 歌曲资源和原唱参考音高

### 4.1 播放资源授权

复用患者歌曲试听接口，显式传 track=source 或 track=accompaniment。扩展 PreviewGrantSource、PatientApi 及其受保护调用，使模式贯穿授权、刷新、播放器和录制交接。授权响应携带或能够关联实际资产标识，切换前后记录的是实际加载成功的资源。

创建演唱会话时，以不可变绑定保存歌曲原曲和伴奏的资产 ID/内容版本。会话录制期间的授权依据会话绑定资源，不依据后来被修改的曲库资源。资产授权继续校验会话所属患者/医生权限和存储回执，不把私有 URL 持久化。

### 4.2 参考音高协议

新增歌曲参考音高资源及 GET /v1/patient/songs/{song_id}/reference-pitch/ 接口；POST /v1/admin/songs/{song_id}/reference-pitch/ 接受可信标注，POST /v1/admin/songs/{song_id}/reference-pitch/generate/ 对真实歌手人声发起幂等生成。响应沿用项目 data/request_id 信封。统一以歌曲起点为时间零点，协议包含 schema_version、资源版本、输入资产 ID 与内容指纹、歌曲时长、算法或标注来源，以及音符区段。区段包含 start_ms、end_ms、midi_note、confidence；区段严格按时间排序且不重叠；时间是整数毫秒，midi_note 在 0–127 内，confidence 在 0–1 内，数值必须有限，开始非负、结束大于开始且不超过歌曲时长；最多 100,000 个区段、正文最多 10 MiB。静音区间不产生区段。

生成优先使用真实 song_vocal 音轨进行单声部音高提取，再按相近半音、置信度和连续时间合并成横块；也允许导入带来源及版本的校验标注。输入为混合原曲时，只有经过真实主旋律提取并验证的结果才可成为原唱参考，普通频谱最高峰或模拟任务的随机数不能用作原唱音高。

本轮采用真实人声音轨提取与可信标注导入两条受控路径，不顺带交付新的歌手人声分离模型。没有歌手人声音轨的存量歌曲需补齐可信标注或真实人声音轨。这属于数据准备，不得把空态认定为必需音高功能完成。

缓存以歌曲 ID、输入内容指纹和参考版本为键，退出账户后取消加载，准备页读取可用版本，录制页固定使用会话绑定版本。参考资源状态为 pending、ready、failed、unavailable，ready 仅在真实内容写入并校验后发布。歌曲声音资产更换后对应参考版本失效并重新生成；会话绑定已选择的版本。重复生成幂等，过期任务不得覆盖新资源。

参考缺失不改变既有“有原曲和伴奏即可演唱”的准入规则；页面显示“原唱音高暂不可用”，患者实时音高仍显示。发布本轮完整体验的验收歌曲必须全部 ready，缺参考的歌曲列入明确的未验收清单。下载失败支持重试且不展示旧歌缓存。

## 5. 安卓播放切换

播放器状态包含已生效模式、请求模式、切换状态、主时钟位置及错误。用户点击另一模式后获取或复用有效授权，加载新资源并恢复原位置；仅资源实际准备就绪后更新已生效模式。

使用现有串行命令、generation/token 和账户作用域隔离。连续快速切换时最后一次请求生效，过期授权不得反向切回。切换失败保留或恢复原模式及其播放位置，显示可重试消息；403 刷新沿用现有限次规则。

演唱期间歌曲逻辑时钟连续。资源缓冲期间麦克风录制继续，时间关系必须由同步元数据表达，不将缓冲造成的停顿隐去。录制主时钟使用单调时间，UI 歌曲轴依据实际播放器时钟；两者通过时间锚点转换。

## 6. 安卓患者采音、音高检测和录制

### 6.1 单一采音源

AudioRecord 成为唯一麦克风采集者，CameraX 视频录制不启用音频。默认 PCM 为 48 kHz、单声道、16 bit；设备不支持时使用 44.1 kHz 并把实际采样率传给检测器和编码器，不用错误采样率计算音高。

同一采样块分发给 AAC 编码与音高检测；检测线程可跳过过期块，录音编码不得因 UI 或检测慢而丢帧。AAC 使用现有可上传 M4A 容器语义，录像输出 H.264/AAC MP4，沿用可信媒体校验及七牛类型处理。无应用层歌曲混音，耳机输入路由使用实际系统采音设备。

保留建议带麦耳机的引导。外放可能产生声学回采，“患者人声”表示患者麦克风录音，不能声称历史外放录音已被算法净化。

### 6.2 实时音高

检测器采用适用于单声部的周期检测，输出 frequency_hz、confidence、采样时间戳。初始处理帧约 40–50 ms，UI 更新约 20 Hz；从收到采样到白点更新的目标延迟不超过 150 ms，在 API 29、API 34 和验收真机测量。

频率映射为 MIDI 半音坐标 `69 + 12 * log2(frequency_hz / 440)`。不按线性 Hz 高度绘制。检测静音、低置信度或无周期输入时输出无音高，白点淡出，轨迹断开。无周期事件不能插值成稳定音符；规则仅表示音高可信度，不声称能够识别嗳气。

图中固定当前时间竖轴，原唱横块按播放时间从右向左移动，竖轴上的白点纵向位置由患者音高决定，已唱轨迹保留在轴左侧。横块和白点共用固定半音坐标；歌曲首次加载时依据参考音域设定显示范围，参考缺失时使用稳定的人声音域，不逐帧缩放。图至少展示最近 2 秒及未来 6 秒。

切换原唱/伴奏、授权刷新、缓冲均不清空参考数据。音高点使用时间锚点映射到歌曲轴，播放器停顿时不把录制时间误当作歌曲时间。

### 6.3 时间戳与输出

摄像录像、PCM 和播放器统一关联单调时钟。周期校准间隔为 5 秒，时间锚点和模式变化随加密草稿持久化，应用恢复/上传重试不得丢失；不持久化实时图形帧或私有播放 URL。记录采集与播放的开始时间、实际播放模式变化及播放/录制时间锚点。锚点在开始、模式切换、缓冲开始/结束及周期校准时产生；若播放器倒退或跳转，则添加新的连续区间，不能覆盖旧区间。

原始视频和 AAC 录制完成后，按有效时间戳合并患者音频到录像；复制现有编码数据，不重新编码患者声音。先把音视频裁到有效重叠区间并统一容器起点，合并失败不得用无声视频冒充完整录像。保留旋转及镜像信息。合并后的录像再走现有单音轨抽取校验，确认 singing_audio 与录像中的患者音轨一致。

首尾、长录制及切换后音视频同步目标偏差不超过 100 ms；医生伴奏/患者音频回放在可对齐区间的目标偏差不超过 100 ms。时间锚点不能修复源歌曲原曲/伴奏本身错位：曲库必须记录并验证相同起点或显式时间偏移，未验证的伴奏不能宣称同步。

只有视频、患者 AAC 和同步元数据均保存成功才进入 Reviewable。权限撤销、音频路由断开、设备占用、磁盘不足、页面退出等沿用显式中断；Finalize 等待两个采集器结束及合并校验，不提前显示保存成功。失败保留现有可恢复草稿规则并清理明文临时文件。重复停止或迟到回调不得重复发布。

## 7. 共同的演唱回放协议

在现有演唱提交协议上增加可选的版本化 playback_metadata，旧客户端可不传。新客户端提交时包含会话绑定资源版本、实际录制采样率、初始播放时间关系、模式变化及播放时间锚点。服务端校验有限数值、录制时间单调、资源属于当前会话；最多 10,000 个锚点、1,000 次模式变化、元数据正文最多 1 MiB。相邻锚点包括 recording_ms、song_ms、track 和 playing；同一连续播放区间的 song_ms 不倒退，显式跳转建立新 segment。服务端持久化为不可变提交快照，重复提交同一幂等键必须校验元数据一致。

医生明细响应增加 playback 描述，明确 patient_audio 来源、本次绑定 accompaniment 资产、同步状态、时间锚点和历史兼容状态。新增 POST /v1/patient/singing-sessions/{session_id}/song-playback/?track=source|accompaniment 为患者授权会话快照歌曲资源；POST /v1/admin/singing-sessions/{session_id}/playback-accompaniment/ 为医生授权该会话伴奏，响应包含资产标识、url 和 expires_at。患者录音及录像复用现有私有 URL 权限入口；播放器刷新签名时保持资产身份、位置及生效模式。

旧会话的 singing_audio 继续作为原始麦克风录音播放。没有可信伴奏版本或时间关系时仅提供患者人声回放，组合选项可见但禁用并解释“本次演唱缺少可同步伴奏”；不自动绑定当前歌曲伴奏，不用歌曲人声补位。历史兼容不伪造新元数据。

## 8. 医生端页面

### 8.1 患者列表

把 /patient-data 占位页替换为真实患者数据列表，复用 listPatients 及服务端权限范围。展示病历号、姓名、医生和治疗状态，提供搜索、医生/状态筛选及分页，点击进入 /patients/:patientId/data；已有患者资料、汇总、历史和明细流程复用。

列表需要加载、错误重试和无数据状态。搜索与分页写入 URL，详情返回恢复筛选。页面以数据查看为主要操作，不复制病人账号管理的创建、停用、密码重置功能。

### 8.2 声音波形与回放

删除截图二对应的独立演唱回放卡片。首次准备媒体、播放/暂停、当前时间、跳转入口与授权错误都归入声音波形卡片。WaveSurfer 总览只读取患者录音，保留真实波形、时间刻度和点击跳转；嗳气事件可在总览标记但不再占一整张回放卡片。

仅两种音轨按钮：“人声＋伴奏”“人声”。组合模式由患者音频和本次绑定伴奏同步播放；人声模式静音或暂停伴奏。患者音频为主时钟，录像避免重复输出自己的患者音轨。切换不创建新患者媒体源、不停止患者音频、不重置时间。结束、拖动、暂停、播放速率变化和缓冲都同步到相关媒体。

### 8.3 双图实时声音看板

按照 design.pen 的唱歌明细实现深色看板：四项指标、左侧黄色/红色分层时序波形、右侧橙色/红色极坐标图。样式参照 H6DDrc、YoqZJ，图形变化由真实患者音频驱动，颜色图层不是不同音轨。看板“实时”指历史录音播放时实时更新。

采用单一 Web Audio 分析器，Canvas 负责双图绘制；WaveSurfer 负责整段录音总览。移除当前 simpleBars 可视化路径，避免静态柱图及多次绑定同一 media element。暂停冻结，继续恢复，跳转清理过期时序窗口，结束显示静止状态，卸载取消动画并释放资源。UI 不再展示与实际实现不符的 Waviz 技术标记。

采样前检查 AudioContext、资源 CORS、实际样本和初始化错误。禁止用随机数据或固定图样回退；无有效数据时显示可视化不可用及重试状态。正确设置跨域方式，必要时在已授权存储/媒体读取边界提供支持采样的响应，不暴露绕过授权的公开音频地址。

音量使用患者采样 RMS 转为 dBFS，并在标题说明口径；基频显示当前可信患者音高，静音显示“—”。信噪比仅在真实算法有明确口径及来源时展示数值，否则显示“暂无真实数据”；旧模拟 SNR 必须标为模拟。嗳气事件从既有协议按回放时间读取，模拟事件显示模拟标记，不用波形推断为真实检测。

## 9. 取景与引导

引导描绘鼻子以下、嘴部、下颌与颈部轮廓，并将准备页、录制页文案改为“请让嘴部、下颌和颈部位于引导区域内”。这是摆位引导，不能显示未经实现的实时人脸合格判断。

引导轮廓不直接裁掉最终录像，保留实际取景中的有效画面。Preview 与 VideoCapture 使用统一宽高比、ViewPort/裁切、方向及前摄镜像策略。预览允许必要的留边，不能通过独立填满缩放掩盖与成片的差异。

390×844 基准及小屏、字体放大时，音高图、模式切换、取景和停止按钮均可见且不互相遮挡；触控区域不小于现有 48 dp 规范。逐段对照同次录制的预览、安卓回看及医生录像确认取景一致。

## 10. 验证与完成标准

| 类别 | 必须验证 |
| --- | --- |
| 患者入口 | 侧栏真实列表、权限、筛选分页、详情返回恢复及错误重试 |
| 歌曲资源 | 原曲/伴奏授权、会话媒体版本固定、参考音高真实生成/导入与旧版本失效 |
| 实时音高 | 已知 110/220/440 Hz、静音、噪声、断续歌唱、倍频误判及检测延迟 |
| 安卓播放 | 两处默认模式、连续切换、失败恢复、过期响应、授权刷新、录制持续及歌曲时间连续 |
| 录制链路 | 单一麦克风、AAC/MP4 输出、同步偏移、长录制、两采集器中断、Finalize 幂等、七牛上传及明文清理 |
| 医生回放 | 两种模式真正改变伴奏播放，患者波形保持一致，录像无重复音频，暂停恢复/跳转/结束/授权刷新 |
| 看板 | 两图设计对照、真实非静音数据响应、静音及不可采样状态、模拟指标标识 |
| 取景 | 鼻子以下及颈部引导、预览/成片一致、小屏及字体放大、前摄方向镜像 |
| 兼容 | 旧客户端提交、旧录音原始回放、无治疗计划、认证工作区改动保留 |

## 11. 实施顺序

先补齐服务端会话媒体快照、同步元数据和歌曲参考资源合同，再实现安卓模式切换与单一采音，最后接通医生列表/回放/看板及两端视觉。纯患者列表与移除独立回放卡片可以独立实现，但整体完成必须经过真实歌曲和同次录制的端到端验收。
