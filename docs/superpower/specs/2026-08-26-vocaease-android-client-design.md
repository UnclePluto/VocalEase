# VocaEase 患者 Android 客户端设计规格

日期：2026-08-26
状态：已确认，待用户审阅书面规格

## 1. 背景与目标

VocaEase 使用唱歌训练辅助胃上嗳气治疗。现有项目已经交付 Django 共享服务、医生后台、患者 API、私有媒体存储协议和模拟分析流程，但尚未包含患者 Android App。

本期交付一个面向中国大陆患者的原生 Android 客户端，完成以下闭环：

1. 患者使用医生后台生成的病历号和初始密码登录。
2. 首次登录强制修改密码。
3. 查看活动治疗计划、完成次数和目标次数。
4. 浏览、搜索和试听已上架歌曲。
5. 播放歌曲时使用前置摄像头同步录制患者演唱。
6. 在本地回看、重录或确认提交。
7. 断网或网络不稳定时加密保存录制并自动续传。
8. 查看上传、分析状态、演唱结果和历史回顾。

客户端的页面视觉以 `docs/design-m.pen` 为主要指导。设计稿中的医生或产品说明只作为视觉与流程参考，不覆盖本规格中经用户确认的产品要求。

## 2. 已确认范围

### 2.1 包含

- Android 10（API 29）及以上竖屏手机。
- 病历号密码登录、Android 刷新令牌轮换、首次强制改密、修改密码和退出。
- “去唱歌”和“我的”两个顶级入口。
- 首页治疗进度、曲库、歌曲试听、演唱准备、演唱录制、本地回看、重录和提交。
- 前置摄像头视频与独立音频两个上传产物。
- 应用私有目录中的加密草稿、上传队列、断点续传和自动重试。
- 上传中、等待网络、分析中、已完成、失败和已取消状态。
- 演唱历史、得分、评分拆解、录像回放和音准回顾。
- 中国大陆网络环境、国产 Android 设备和无 GMS 运行。
- 与现有 Django API、七牛云私有空间及模拟分析协议联调。

### 2.2 不包含

- 患者自助注册、手机号验证码登录或账号找回。
- 平板、横屏、折叠屏专项布局和 Android 10 以下设备。
- 训练提醒、定时通知或医生下发推送。
- Firebase、FCM、Google 登录、Google 地图、Google ML Kit、Play Integrity、Play Billing 和 Play 应用内更新。
- Google Play 商店作为唯一分发渠道。
- 客户端实时 AI 推理、临床诊断或真实算法实现。
- Android 端编辑患者资料或治疗计划。
- 医生后台的新页面设计。

## 3. 设计稿基线

Pencil MCP 已读取 `docs/design-m.pen`。原稿包含五个 390 × 844 画板：

- `01-歌曲列表页`
- `02-演唱准备页`
- `03-演唱页`
- `04-我的`
- `05-演唱回顾页`

原稿使用双标签导航：“去唱歌”和“我的”。该结构必须保留，不引入首页、曲库、历史、个人中心四标签方案。

已在 Pencil 画布中保留原首页，并新增 `01A-歌曲列表页-治疗进度版` 作为确认后的首页变体。变体用治疗进度替换“今日推荐”Banner，保留“今天唱什么？”、搜索、热门歌曲和双标签导航。

视觉变量：

- 主色：`#28C985`
- 深主色：`#12885A`
- 深色背景：`#0B3325`
- 页面背景：`#F6FAF7`
- 柔和背景：`#EAF4EE`
- 卡片：`#FFFFFF`
- 主文字：`#17211D`
- 次文字：`#7A8780`
- 边框：`#DEE8E2`
- 录制色：`#F0545E`
- 字体：`Noto Sans SC`

浅色页面用于登录、首页、准备、我的和回顾；演唱录制页保持原稿的沉浸式深色界面。原稿的圆角、留白、列表密度、图标语言和触控区域作为 Compose 实现的视觉基准。

## 4. 技术方案与仓库边界

采用 Kotlin 原生 Android 模块化单体：

```text
VocaEase/
├── android-patient/       # 患者 Android 客户端
│   ├── app/               # 单一 Gradle 应用模块
│   ├── build.gradle.kts
│   └── settings.gradle.kts
├── server/                # 现有 Django 服务
├── web-admin/             # 现有医生后台
├── deploy/
└── docs/
```

首期只建立一个 `app` Gradle 模块，内部按功能和职责分包；不提前拆分多个 Gradle feature 模块。包边界至少包括：

- `feature.auth`：启动会话、登录、首次改密、修改密码和退出。
- `feature.catalog`：首页治疗进度、歌曲列表、搜索、详情和试听。
- `feature.training`：准备检查、播放、录像、回看和本地草稿。
- `feature.upload`：上传任务、续传、确认、提交和状态同步。
- `feature.history`：历史列表、处理状态和演唱回顾。
- `feature.profile`：患者资料、治疗计划、待上传记录和设置。
- `core.network`：认证请求、令牌刷新、API 错误和请求追踪。
- `core.database`：Room 数据库和迁移。
- `core.media`：CameraX、Media3、音轨抽取和本地文件。
- `core.security`：Keystore 密钥、令牌和文件加密。

界面使用 Jetpack Compose。每个页面由 ViewModel 暴露不可变 UI 状态并接收用户事件；页面不直接访问网络、数据库、相机、文件或上传 SDK。数据层通过 Repository 统一远端和本地来源。复杂训练与上传流程使用显式状态机，避免把业务状态散落在 Composable 中。

## 5. 中国大陆与零 GMS 约束

运行时不得依赖 Google 移动服务或 Google 在线接口。Compose、CameraX、Room、WorkManager 和 Media3 作为打包进 APK 的 AndroidX 库使用，不要求设备安装 Google Play 服务。

构建期允许使用 AndroidX，但必须：

- 固定依赖版本和校验值，不使用动态版本。
- 通过国内可访问的 Maven 代理或内部制品缓存获取依赖。
- 让 CI 在无法访问 Google 域名时仍可重复构建。
- 审计完整运行时依赖树，拒绝间接引入 Play Services 或 Firebase。

应用运行时只访问 VocaEase API、七牛云私有存储以及 Android 系统本地能力。APK 可通过国内应用市场、医院内部渠道或直接安装包分发。

## 6. 页面与导航

### 6.1 启动与认证

```text
启动
├── 有效会话 → 去唱歌
├── 可刷新会话 → 刷新成功后进入去唱歌
└── 无有效会话 → 登录
                     └── must_change_password=true → 首次强制改密 → 重新登录
```

不提供注册入口。患者账号由医生后台创建，病历号作为登录账号，初始密码为 `888888`。改密成功后原令牌失效，客户端清除令牌并返回登录页。

### 6.2 顶级导航

主界面只包含两个底部入口：

- 去唱歌：治疗进度、曲库和训练入口。
- 我的：演唱统计、历史、计划、待上传记录和账户设置。

登录、改密、准备、录制、回看、上传状态和演唱回顾页不显示底部导航。

### 6.3 完整页面流

```text
去唱歌
└── 歌曲列表
    └── 演唱准备
        └── 演唱录制
            └── 本地回看 / 试听
                ├── 重新录制
                └── 确认提交
                    └── 上传中 / 等待网络
                        └── 分析处理中
                            └── 演唱回顾

我的
├── 演唱统计
├── 演唱历史 → 演唱回顾
├── 治疗计划详情
├── 待上传记录
└── 设置 → 修改密码 / 退出登录
```

## 7. 首页与治疗计划

“去唱歌”是登录后的默认首页。设计稿原“今日推荐”Banner 替换为治疗进度 Banner，展示：

- 活动治疗计划的已完成演唱次数。
- 计划目标演唱次数。
- 完成百分比，上限 100%。
- 根据开始日期和周期计算的当前治疗周数。
- 继续训练的简短提示。

如果患者没有活动治疗计划，Banner 显示“暂无进行中的治疗计划，请联系医生”，歌曲列表和开始训练入口不可用，但患者仍可进入“我的”查看资料和历史。

存在待上传、上传失败或分析失败任务时，首页在治疗进度 Banner 下方显示一条轻量状态提示并链接到“我的 → 待上传记录”；它不新增底部标签，也不挤占治疗进度 Banner。

首页不展示提醒设置，不申请与训练提醒相关的通知权限。后台上传使用 Android 系统要求的持续任务通知，不属于训练提醒。

## 8. 曲库与试听

- 只展示服务端返回的已发布且媒体可用歌曲。
- 支持关键词搜索和分页追加加载。
- 歌曲卡片沿用设计稿的封面色块、标题、歌手、时长和右箭头。
- 点击歌曲进入演唱准备页。
- 试听和正式训练播放均通过服务端短时私有地址。
- 播放地址过期时自动刷新；刷新失败才显示可操作错误。
- 开始训练前预缓冲歌曲，缓冲完成后才允许进入倒计时。

## 9. 演唱准备与录制

准备页保持设计稿内容：歌曲信息、歌词预览、完整露出面部提示、带麦耳机建议、设备状态和开始按钮。

规则：

- 前置摄像头和麦克风权限均为必需。
- 耳机优先但不强制；允许扬声器播放，并提示可能产生串音。
- 倒计时前检查相机、麦克风、可用存储空间和歌曲缓冲状态。
- 患者必须在线创建新的服务端演唱会话；会话创建成功后，即使网络中断也能完成本次录制、回看和本地保存。
- 录制页保持深色沉浸式视觉，显示音准轨迹、动态歌词、前摄画面、录制时间、面部状态和结束按钮。
- 录制期间保持屏幕常亮并锁定竖屏。

媒体采集采用一个麦克风来源：CameraX 录制前摄视频和麦克风音轨，Media3 同步播放歌曲。录制结束后使用 Android 媒体能力从视频容器中无损抽取独立音频文件。服务端最终收到 `singing_video` 和 `singing_audio` 两个产物，但客户端不同时启动两个麦克风采集器。

默认在歌曲结束时自动停止，患者也可提前结束。提前结束仍进入本地回看，不自动提交。

## 10. 本地回看与草稿

结束录制后必须先进入本地回看页，不直接进入最终得分页。患者可以：

- 播放录像和独立音频。
- 查看录制时长与基础文件检查结果。
- 删除本次录制并重录。
- 确认提交并进入上传流程。

来电、切后台、相机被其他应用占用或进程异常时，客户端尽可能正确结束并封装已有媒体。可播放的片段保存为“未完成草稿”，只能重录或删除，不提交分析。

## 11. 上传、续传与提交

确认提交后：

1. 将已有本地草稿转换为待上传任务，并确保音频、视频和任务状态已持久化到 Room。
2. 文件继续保存在应用私有加密目录。
3. 分别向服务端申请音频和视频上传凭证。
4. 七牛正式环境使用 Android SDK 的分片上传 V2 和本地断点记录。
5. 上传完成后等待七牛可信回调，再分别调用服务端确认接口。
6. 两份媒体都确认就绪后，使用幂等键提交分析任务。
7. 页面明确区分上传中和分析中。

WorkManager 负责跨进程、重启和网络恢复的持久任务调度。长时间后台上传使用系统要求的前台任务通知。患者可暂停、继续、立即重试或删除尚未提交的上传任务。

上传凭证过期后重新申请同一媒体绑定的凭证。创建会话、获取凭证、确认上传和提交分析均使用稳定幂等键；网络超时后的重试不得产生重复会话、媒体或分析任务。

## 12. 历史与演唱回顾

“我的”沿用设计稿的问候、演唱总歌曲数、演唱总时长和历史列表。待上传、上传中、分析中和失败记录也进入历史列表，并使用状态而非虚构分数展示。

最终回顾页沿用设计稿：

- 歌曲与演唱得分。
- 私有录像回放。
- 音准、节奏和稳定度评分拆解。
- 音准回顾曲线。

模拟分析数据只在 `is_mock: true` 时于得分标题旁低调显示“演示结果”；`is_mock: false` 时不显示额外标识。不展示“非临床结论”文案。

## 13. 本地数据与隐私

- 访问令牌只保存在内存；刷新令牌和本地文件密钥受 Android Keystore 保护。
- 音视频保存在应用私有目录并加密，不写入公共相册或共享存储。
- Room 保存患者作用域、服务端会话 ID、媒体摘要、上传状态、断点记录引用、重试信息和清理时间，不保存永久私有媒体 URL。
- 不同患者账号不能读取、播放或续传对方草稿。
- 服务端确认上传并成功提交分析后删除本地音视频，只保留必要状态和缩略信息；后续回放使用服务端短时私有地址。
- 未提交草稿默认保留 7 天，临近清理时在“我的 → 待上传记录”提示。
- 退出登录时询问是否保留待上传草稿。保留的草稿暂停并锁定，只能由同一账号再次登录后恢复。
- 卸载应用时由系统删除应用私有数据。
- 日志不得包含密码、JWT、刷新令牌、上传凭证、完整私有地址、手机号、病历备注或本地明文媒体路径。

## 14. 错误与恢复

- 权限被拒绝：说明用途并提供系统设置入口；缺少相机或麦克风权限时不能开始训练。
- 存储不足或设备不可用：倒计时前阻止录制。
- 播放地址过期：自动刷新并重新预缓冲。
- 录制意外中断：保留可播放草稿，不上传残缺文件。
- 上传失败：指数退避自动重试，同时提供暂停和手动重试。
- 登录过期：自动刷新一次；刷新失败返回登录页，待上传媒体加密保留并暂停。
- 服务端返回状态冲突：先重新获取会话真实状态，再决定继续上传、提交、展示结果或停止操作，不盲目重复创建。
- 分析失败：展示可理解原因和“重新分析”入口；调用现有患者重试接口并遵守最大尝试次数。
- 所有患者可见错误使用简明中文，不显示接口码、堆栈、对象键或存储地址。

## 15. 服务端适配

现有患者 API 继续使用 `/api/v1/patient/`，通用认证继续使用 `/api/v1/auth/`。需要同步调整：

1. 扩展患者本人接口，返回活动计划的已完成次数、目标次数、治疗进度和当前周数。
2. 创建演唱会话接口接受幂等键，并保证相同患者、相同幂等键只产生一个会话。
3. 提交演唱接口从“音频必需、视频可选”调整为音频和视频均已确认才允许提交。
4. OpenAPI Schema 明确 Android 登录、上传凭证、媒体确认、会话状态和结果字段。

以下能力已经存在并复用：

- Android 刷新令牌通过响应体返回并轮换。
- 患者本人资料和活动治疗计划。
- 患者曲库、歌曲详情和短时试听地址。
- 会话创建、上传凭证、媒体确认、提交、取消、重试、列表和详情。
- 音频 `audio/mp4` 与视频 `video/mp4` 媒体类型。
- 患者私有媒体短时访问地址。
- 分析结果、时间序列和 `is_mock` 字段。

## 16. 测试与验收

### 16.1 自动化测试

- 单元测试：认证状态、首次改密、治疗进度映射、录制状态机、上传队列、幂等键、重试、草稿清理和错误映射。
- Room 测试：实体约束、患者隔离、迁移和重启恢复。
- Compose 测试：登录、首页进度、歌曲列表、准备、回看、上传状态、历史和回顾。
- API 契约测试：Android 数据模型与 OpenAPI Schema 一致。
- 媒体测试：固定样本的播放、封装检查、音轨抽取、加密写入和解密读取。
- 服务端回归：会话创建幂等、视频必传、患者进度字段和现有 Web 管理端不受影响。

### 16.2 集成与端到端

- 使用七牛测试私有空间验证分片、断点、暂停、恢复、凭证过期、重复回调和完整性确认。
- 使用固定媒体完成：登录并改密 → 查看进度 → 选择歌曲 → 创建会话 → 上传 → 分析 → 查看历史和回顾。
- 验证杀进程、重启设备和网络切换后上传队列恢复。
- 验证不同患者无法访问彼此草稿或私有媒体。

### 16.3 真机与视觉验收

- 覆盖 Android 10 最低版本、一个主流中间版本和当前最新稳定版本。
- 重点覆盖小米、荣耀、OPPO、vivo，以及可安装 Android APK 的华为兼容机型。
- 在未安装 Google Play 服务且无法访问 Google 域名的设备上完成全闭环。
- 真机验证播放与录制并行、前摄方向、蓝牙/有线耳机、扬声器串音、来电、切后台、存储不足和国产系统后台限制。
- 按 `design-m.pen` 对主要页面截图比对，覆盖 390 × 844 基准、常见手机宽度和较大字体设置。
